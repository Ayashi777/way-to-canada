# Політика вмісту GitHub Pages

Сайт є згенерованою консолідацією публічних Markdown-документів репозиторію, а не окремою вручну підтримуваною вітриною.

## Єдине джерело даних

`scripts/build-site.mjs` читає лише явний allowlist безпечних Markdown-документів: стартову сторінку, актуальний план, контрольні точки, рішення, тематичні документи `docs/`, місячний журнал, знеособлені дослідження, шаблони та документацію структури репозиторію. Кожен файл із цього переліку перетворюється на розділ одного сайту, а головний план додатково формує блок «Що важливо зараз».

Під час кожного push у `main` єдиний workflow `.github/workflows/pages.yml` створює `dist/index.html` і публікує лише папку `dist` у GitHub Pages.

## Межі безпеки

Будівник не обходить файлову систему й не читає `private/`, Telegram-експорт, SQLite, вкладення або інші не включені явно файли. Не додавайте такі джерела до allowlist. Перед зміною публічного документа перевіряйте, що він не містить персональних даних, цитат із приватних чатів або закритих запрошень.

## Як оновити сайт

1. Оновити першоджерело Markdown: план, контрольні точки, журнал, рішення або дозволений артефакт.
2. За потреби локально виконати `node scripts/build-site.mjs` і переглянути `dist/`.
3. Закомітити лише вихідні публічні файли; `dist/` не комітиться.
4. Після push GitHub Actions збере й задеплоїть нове відображення автоматично.

На сайті немає інтерактивного відмічання виконання. Стан змінюється лише через оновлення джерельних документів і журналу.

`dist/` у чистому середовищі CI створюється заново. Локальна збірка оновлює лише відомі файли артефакту, тому її можна запускати під час роботи локального сервера.
