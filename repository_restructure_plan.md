# План реструктуризації репозиторію

Дата: 2026-09-15  
Статус: запропонована базова структура створена; наповнення додається після перевірки фактів.

## Призначення

Репозиторій є публічним, безпечним журналом підготовки до Канади. Він має відповідати на п'ять питань: що зроблено, чому прийнято рішення, де доказ, що змінилося і який наступний крок. Він не є сховищем персональних документів.

## Структура

```text
/
├── README.md                         # стартова сторінка і правила користування
├── repository_restructure_plan.md    # цей план міграції
├── docs/
│   ├── master-plan.md                # актуальний план за напрямами
│   ├── decisions.md                  # журнал важливих рішень
│   ├── timeline.md                   # дедлайни й контрольні точки
│   ├── private-materials-index.md    # публічний індекс без вмісту приватних файлів
│   └── immigration/
│       ├── status-and-visas.md       # безпечний опис статусів і наступних перевірок
│       └── official-sources.md       # стислий реєстр офіційних джерел
├── journal/
│   ├── template.md                   # шаблон запису
│   └── 2026-09.md                    # поточний місячний журнал
├── artifacts/
│   ├── research/README.md            # перевірені дослідження без персональних даних
│   ├── templates/README.md           # шаблони листів, чеклістів і таблиць
│   └── references/README.md          # безпечні зовнішні довідники
└── private/                          # лише локально, виключено з Git
    ├── documents/
    ├── personal-data/
    └── telegram-export/
```

`private/` навмисно не створюється як відстежувана папка: вона виключена через `.gitignore` і має існувати лише на локальному комп'ютері.

## Порядок міграції наявних матеріалів

1. Винести з публічного простору всі особисті файли до локального `private/`.
2. Для кожного приватного документа додати лише безпечний рядок у `docs/private-materials-index.md`: тип, призначення, дата перевірки, наступна дія. Не вказувати номер, адресу, ПІБ або шлях до файлу.
3. Перенести перевірені висновки з досліджень у тематичні файли `docs/`; кожне твердження про правила IRCC має містити URL першоджерела й дату перевірки.
4. Додати короткі артефакти без чутливих даних у `artifacts/` з назвою `YYYY-MM-DD-тема.md` та посиланням на джерело.
5. Після кожної суттєвої дії додавати один запис у поточний файл `journal/YYYY-MM.md`.
6. Перед комітом перевіряти `git status` і переконуватися, що `private/`, Telegram-експорт, бази SQLite, документи й секрети відсутні у списку.

## Правило для GitHub Pages

Сайт показує лише актуальний план, статус напрямів, найближчі кроки та посилання на безпечні публічні документи. Чекліст на сторінці не є журналом виконання: зміни статусу вносяться лише після узгодженого щоденного огляду та фіксуються в `journal/` і, за потреби, у `docs/decisions.md`.
